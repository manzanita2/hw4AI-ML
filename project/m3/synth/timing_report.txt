# Source:  OpenLane 2 step 38-openroad-stamidpnr-2 (post-resizer STA),
#          nominal typical corner (nom_tt_025C_1v80, 25 degC, 1.80 V).
# Run:     project/m3/synth/runs/RUN_2026-05-24_18-50-37/
# RTL:     compute_core_pipelined w/ pe_pipelined (MAC_LATENCY = 8)
#          + per-PE FSM-broadcast staging w/ disjunct trick (Phase 5)
#          + ASYNC-RESET RTL across every m3/rtl/*.sv (Phase 8)
#          + EGRESS SKID BUFFER (Phase 9)
#          + FIFO_SYNC SPLIT + WS REGISTERED READ (Phase 10)
#          + MUL_BF16_P3 (Phase 11): replaces mul_bf16_p2 (2 stages,
#            8x8 mantissa multiply in one stage). The new module does
#            a "B-half radix-4 split" -- two 4x8 -> 12-bit half-products
#            in stage 1 (parallel), 16-bit shift-add CPA in stage 2,
#            normalize/exp/pack in stage 3. Bit-exact equivalent to the
#            m2 reference; PE pipeline depth bumps 7 -> 8 cycles.
# Target:  3.333 ns / 300 MHz (architecture.md spec).
#
# Headline (iter 7, after mul_bf16_p2 -> mul_bf16_p3 radix-4 split):
#   Setup WNS (post-resizer, typical corner): -1.130 ns
#   Setup TNS (post-resizer):                 -611 ns
#   clk period_min:                            4.46 ns -> ~ 224 MHz
#   Hold WNS (post-resizer):                  -0.268 ns (resizer pending)
#
# Delta vs iter 6 (RUN_2026-05-24_16-50-18, fifo_sync split + ws):
#   period_min Fmax:    4.54 -> 4.46 ns        (+ 4 MHz, +1.8 %)
#   post-resizer WNS:  -1.207 -> -1.130 ns     (+ 0.077 ns; modest)
#   post-resizer TNS:  -1072 -> -611 ns        (-43 %; big)
#
# What the radix-4 split actually accomplished (the "0.6-0.9 ns
# recovery on the bf16 mul stage 1 class" predicted by the iter-7
# plan; the headline shift is bound by the next-worst class):
#
#   Iter-6 #1 violator class: bf16 mul stage 1 partial-product reduce
#       Endpoint:  u_pe.u_mul.s1_mant_prod[15]/D
#       Slack:     -1.207 ns at 3.333 ns target
#       Cause:     14 sky130 cell levels of the 8x8 mantissa multiply
#                  (PP-gen + reduce + sum/carry) all in one pipeline
#                  stage between act_reg and s1_mant_prod
#   ELIMINATED. The mul_bf16_p3 endpoint that takes its combinational
#   place is `prod_lo_c[k]/D` and `prod_hi_c[k]/D` -- two 4x8 -> 12-bit
#   sub-multipliers in parallel. The worst path landing on those new
#   endpoints has slack -0.34 .. -0.58 ns at 3.333 ns target. So this
#   class is still violating, but by 0.6-0.9 ns less than iter 6.
#   Headline recovery on this class alone: +0.6 .. +0.9 ns.
#
# Why setup WNS only moved 0.08 ns:
#
#   The new top violator was iter 6's #2 class (queued for iter 7's
#   mirror skid). It is a single startpoint with ~ 30 violating
#   endpoints (all paths from u_ing_fifo.rd_ptr[0] into the ingress
#   FIFO read mux):
#
#     Startpoint:  u_ing_fifo.rd_ptr[0]              (sky130 dfrtp_2)
#     Endpoint:    a flop in compute_core that captures one of the
#                  ingress FIFO output bits as the row activation feed
#                  (sky130 dfxtp_2)
#     Slack:       -1.130 ns at 3.333 ns target
#
#   Path: rd_ptr[0]/Q -> 6 buf hops (rd_ptr fanout + repeaters)
#           -> xnor2 / nand3b / nand4 (mux decode start)
#           -> 5 more buf hops (rebuffer / fanout / load_slew of mux
#              control over a wide select cone)
#           -> mux2_1/S -> dfxtp_2/D
#
#   ~ 1.0 ns of post-rd_ptr fanout buffering + ~ 0.7 ns of mux decode
#   + ~ 1.5 ns of post-decode select-line buffering + ~ 0.6 ns of
#   mux2 + setup. The 257-bit-wide FIFO read mux x 4 entries deep
#   has rd_ptr driving a huge select-line fanout; the resizer cannot
#   rebuild that without a flop in front of the mux output.
#
# Critical path summary (post-resizer; full walk in critical_path.md):
#
#   New WNS path (ingress FIFO read mux):
#     u_ing_fifo.rd_ptr[0]/Q (1.73 ns; clk-Q + first buffer)
#     -> 6 buffer hops to xnor2/nand3b/nand4 mux decode (2.76 ns)
#     -> 5 more buffer hops to mux2/S (5.11 ns)
#     -> mux2_1/X -> dfxtp_2/D (5.43 ns)
#     Slack: -1.130 ns
#
#   2nd class (load_seq -> ws.rd_data_q mem mux):
#     u_lseq.cnt[1]/Q (1.67 ns)
#     -> nor2 -> dlymetal -> clkdlybuf -> and3b -> a22o -> a221o
#        -> a211o -> a221o -> o22a (mem mux at 4x4 = 16:1 mux,
#                                   ~ 9 cells of mux + setup)
#     -> dfxtp_2/D (5.16 ns; rd_data_q from iter 6)
#     Slack: -0.862 ns
#   This is the iter-6 plan's "Risk #3" coming home: at 4x4 the
#   weight_store mem is 16 entries deep; at 48x48 it's 2304 entries
#   deep, so the projected 48x48 slack on this class is much worse.
#
#   3rd class (bf16 mul stage 1 *after* radix-4 split):
#     u_pe.weight[k]/Q
#     -> ~ 8 cells of partial-product AND + 1-level reduce
#     -> u_pe.u_mul.prod_lo_c[k]/D or prod_hi_c[k]/D
#     Slack: -0.34 .. -0.58 ns
#   The radix-4 split reduced this class by ~ 0.6-0.9 ns. Further
#   recovery requires either (a) a 4th stage of partial-product
#   reduce, or (b) an even narrower split (e.g. radix-2 = 2x8 sub-
#   multiplies + radix-2 add tree).
#
# Sustained throughput @ ~ 224 MHz, 16 PEs (M = N = 4):
#       2 * 16 * 224e6 = 7.17 GFLOP/s peak (1 mac/cycle/PE)
# Projected sustained throughput @ ~ 224 MHz, M = N = 48:
#       2 * 2304 * 224e6 = 1.032 TFLOP/s peak (75 % of 1.38 TFLOP/s spec)
# AXIS-256 b ingress @ 224 MHz: 7.17 GB/s (1 % over the 7.11 GB/s spec)
#
# Bottom line: the radix-4 split fixed exactly what the plan said it
# would fix at the path level: bf16 mul stage 1 dropped ~ 0.7 ns of
# slack. The headline WNS only moved 0.08 ns because the queued
# iter-7 #2 violator (ingress FIFO read mux) was already at -0.88 ns
# in iter 6 and is now exposed. To close 300 MHz from here, we need
# (a) ingress skid buffer (mirror of iter 5's egress skid) -- ~ 1.0
# ns recovery, AND (b) further weight_store mem mux pipelining
# (the 4x4 mem mux is 16:1; 48x48 mem mux is 2304:1) -- ~ 0.5 ns
# recovery. The bf16 mul itself is one more split away from being a
# non-issue (radix-2 instead of radix-4 = 4-stage multiplier).
#
# What's below this header is the verbatim openroad report_checks
# dump (step 38 stamidpnr-2, post-resizer): the new WNS path
# (ingress FIFO read mux), the 2nd-class path (load_seq -> ws mem
# mux -> rd_data_q), and the 3rd-class path (bf16 mul stage 1 after
# radix-4 split, weight -> prod_lo/prod_hi).
